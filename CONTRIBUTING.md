# Contributing to Awesome LoomLoom

Thank you for helping people find useful LoomLoom projects.

## What belongs here

Add a project only when it has a public, stable link and a clear relationship to LoomLoom. Suitable entries include:

- End-user applications built with LoomLoom.
- SDKs, API clients, developer tools, and integrations.
- Reusable templates, SkillBots, starters, and runnable examples.
- Tutorials and learning resources with enough detail to reproduce their result.

Do not add unrelated AI products, generic link collections, private repositories, referral links, copied content, or projects that falsely claim official support.

## Before opening a pull request

1. Check that the project is not already listed.
2. Choose the most specific section in `README.md`.
3. Verify the project URL, license, and stated LoomLoom compatibility.
4. Use the standard entry format and keep the description factual and concise.
5. Put entries in alphabetical order within a section once the section contains projects.

## Required entry information

Every project entry must include a public canonical URL, one-sentence description, provenance label (`Official`, `Community`, or `Experimental`), LoomLoom compatibility (or `Not stated by maintainer`), project license (or `License not stated`), and status (`Active`, `Maintenance`, `Archived`, or `Unknown`).

For templates and SkillBots, also disclose required external services and expected per-run costs when known. Never include credentials, private endpoints, or paid claims that cannot be verified.

## Submission paths

- Use the **Add a community project** issue form if you want maintainers to review a proposed entry first.
- Open a pull request for a ready-to-merge listing or a correction.

Maintainers may edit an entry for consistency, move it to another category, request evidence, or decline it when the relationship to LoomLoom is unclear.

## Ownership and endorsement

Listing a project is discoverability, not certification, security review, compatibility guarantee, commercial partnership, or official support. Project maintainers remain responsible for their code, licenses, operational costs, and user-facing claims.
